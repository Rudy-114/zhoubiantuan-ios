# Admin Web Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a real `/admin` operations console for one human operator to review safety cases, automatic actions, corrections, appeals, existing pre-publication moderation, user risk, audit events, trusted devices, and AI health.

**Architecture:** Serve a no-build ES-module app from Express with strict self-only CSP. Use a quiet fixed sidebar, compact toolbar, dense queue table, and one detail inspector instead of dashboard-card mosaics. The backend admin case API owns pagination, filtering, evidence authorization, audited decisions, and existing moderation-review migration; browser code owns device-key storage, signed auth challenges, navigation, and optimistic-but-reconciled UI state.

**Tech Stack:** Semantic HTML, modern CSS, browser ES modules, WebCrypto, IndexedDB, Express static hosting, Node unit/integration tests, Playwright CLI for real-browser snapshots and screenshots.

## Global Constraints

- REQUIRED UI SUB-SKILLS during implementation: `frontend-skill` and `ui-ux-pro-max`.
- REQUIRED browser verification skill: `playwright` CLI workflow; do not add `@playwright/test` unless Rudy explicitly requests test files.
- Visual thesis: a quiet trust-and-safety control room using near-white and charcoal surfaces, one restrained rose accent from the app, tabular numbers, thin dividers, and explicit status text.
- Content plan: navigation, live workload strip, filterable queue, case inspector, focused decision dialog. There is no hero or marketing copy.
- Interaction thesis: 180ms inspector slide/fade, immediate row status reconciliation after actions, and restrained loading skeletons; respect `prefers-reduced-motion`.
- No page section is styled as a floating card. Cards are reserved for individual evidence items and modal dialogs.
- Base text is at least 14px desktop and 16px in mobile forms; interactive targets are at least 44px.
- Color never carries status alone; every status has text and, where useful, a simple shape marker.
- All icon-like controls have text labels or accessible labels. With no icon library in the repository, prefer clear text commands over hand-drawn SVG.
- Raw private-message evidence is hidden until an explicit audited reveal action.
- Account restriction, permanent removal, appeals, and reversal of manual decisions require single-case confirmation and a reason; they are never bulk actions.
- The browser stores only non-exportable private keys and device IDs, never passwords, sessions, recovery codes, evidence caches, or API keys.
- Admin HTML, JS, and CSS load only from the same origin; no CDN, analytics, external fonts, or third-party scripts.

- [x] **Step 4: Implement audited evidence reveal**

`GET /cases/:id?evidence=metadata` is default. `GET /cases/:id/evidence/:evidenceId` requires a non-empty access reason query or header, inserts an audit event before returning the text/structured snapshot plus same-origin object URLs. - [x] **Step 3: Implement non-exportable key storage**

```js
export async function getOrCreateDeviceIdentity() {
  const existing = await readIdentityFromIndexedDB();
  if (existing?.privateKey && existing?.publicKeyJWK && existing?.deviceID) return existing;
  const pair = await crypto.subtle.generateKey(
    { name: "ECDSA", namedCurve: "P-256" },
    false,
    ["sign", "verify"]
  );
  const identity = {
    deviceID: crypto.randomUUID(),
    privateKey: pair.privateKey,
    publicKeyJWK: await crypto.subtle.exportKey("jwk", pair.publicKey)
  };
  await writeIdentityToIndexedDB(identity);
  return identity;
}

export async function signChallenge(identity, payload) {
  const bytes = new TextEncoder().encode(payload);
  const signature = await crypto.subtle.sign({ name: "ECDSA", hash: "SHA-256" }, identity.privateKey, bytes);
  return bytesToBase64URL(new Uint8Array(signature));
}
```

Store the `CryptoKey` directly in IndexedDB. Never export the private key or fall back to localStorage.
