本次诊断修复的部署约束（持续更新）

当前为本地实施、隔离验证阶段，未发布业务服务、未执行生产数据库迁移。生产证书更换已单独完成。

1. 认证：先应用迁移 013。历史 `ADMIN_EMAILS` 不再授予管理员权限；对已验证邮箱的实际管理员账号执行 `node scripts/moderator.js grant USER_ID`。未验证的历史邮箱必须先完成验证码登录，不能自动批量信任。
2. 上传：迁移 014 新增上传凭据记录和图片索引。`POST /uploads/presign` 保留原响应结构，但 PUT 地址变为 API 单次上传入口。API 校验 10 MB、实际 JPEG/PNG/WebP、2500 万像素，重新编码 JPEG 后写入 `guarded/<kind>/...` 的私有对象。反向代理须允许 `/api/uploads/*` 的 10 MB 请求，设置有限的上传超时；建议 `client_max_body_size 10m`、`client_body_timeout 30s`。上传图片不再直接暴露 OSS PUT 地址，生产安装需包含 sharp 当前平台的可选二进制依赖，不能复制 macOS 的 node_modules 到 Linux。
3. 图片读取：所有新 API 响应使用 `/api/assets/...`，每次检查公开状态或登录用户权限，响应 `private, no-store`。iOS 更新会为本 API 图片带登录令牌、把旧 CDN 图片地址改写到 API，并清除旧图片磁盘缓存。必须同时发布 iOS 更新；旧客户端无法继续匿名读取私信/待审核图片，这是权限生效的必要变化。
4. CDN/OSS：**仅更新业务代码不能关闭旧的 CDN 直读入口。** 部署时必须禁止 CDN 回源直接读取 `message/*` 和 `guarded/*`，并清理旧私信缓存。为让已公开帖子下架后旧 URL 也失效，还需将旧图片域名的回源切到图片权限网关并对全部路径关闭 CDN 缓存（转发 `/post/...`、`/avatar/...`、`/background/...` 到 `/api/assets/...`），或停用旧 CDN 域名。不要保留可绕过权限网关的 OSS/CDN 回源入口。检查 OSS Bucket/Object ACL 为私有；已有公开 ACL 对象需单独收回。部署后用匿名、作者、参与者、无关账号分别验证公开、待审核、私信、撤回、下架图片，再确认 CDN 旧 URL 同样受限。
5. 数据保留：每小时清理已存在超过 7 天、尚未被帖子/资料/私信引用的上传；失败项保留记录以便重试。已引用图片不会因时间经过而被清理。旧 OSS 对象的清理不在这个任务里自动猜测执行。
6. 审核：文本不再截断，采用带重叠的分段；原图和预览图全部进入审核，缺失/异常返回转人工复核。服务端限制正文、数组、账号提交频率及同时审核数。审核时间超限转人工复核。未调用真实付费审核服务做测试。
7. 同步：迁移 015 需要短暂独占 sync_events 表，并移除旧 bigserial 默认分配。必须先停止旧业务写入，备份后执行迁移并启动新后端，不能让旧、新后端混用游标写入。迁移会让旧游标重新初始化一次。所有以后新增的事务处理必须把同步事件写入放在业务写入之后，写事件后不再获取其他业务行锁，以维持统一锁顺序。

实现依据：[阿里云审核智能体响应格式](https://help.aliyun.com/zh/document_detail/3013147.html)、[阿里云文本服务输入限制](https://help.aliyun.com/en/document_detail/2671445.html)、[sharp 安装条件](https://sharp.pixelplumbing.com/install/)、[sharp 图像处理安全参数](https://sharp.pixelplumbing.com/security/)。

本地检查证据：后端 19 项单测、13 项数据库/HTTP 集成测试通过；图片请求改动后的 iOS Release 模拟器构建通过。后续批次会继续更新最终完整验证结果。

8. 发帖：迁移 016 新增请求指纹。新客户端等待服务端确认后才清空草稿，网络重试复用提交编号；重新投稿由服务器原子替换旧帖。必须与本轮客户端一起发布，历史旧帖不会自动补造提交指纹。

9. 库存/合集：迁移 017 为帖子和合集增加自动递增版本，并给缺少编号的历史角色补稳定编号（不改数量、价格）。PATCH 必须携带当前 revision，冲突返回 409，旧版客户端需更新。帖子创建和移动须使用作者自己的有效合集，删除非空合集返回 409。角色文字变动重新审核，数量/调价变动仅允许原本公开的帖子。历史异常角色数据应先审计再人工修正，不能猜测库存或价格；本次没有批量修改业务数量。

10. 举报：迁移 018 增加证据快照、处理人、分页索引，并将去重改为同一目标仅一个待处理记录。部署后用普通用户、无关用户和已验证管理员分别验收：四类入口、我的举报、管理员队列、版本冲突、下架后的内容/图片失效。管理员只可读取被举报的所选私信图片，记录处理后权限撤销。历史举报没有快照，界面明确标示，不能把当前内容伪装成举报时证据。

11. 分页：迁移 019 增加内容游标索引。feed 支持作者、合集、收藏/赞过/关注及文字/有货角色搜索；合集、用户、评论有独立分页端点。帖子详情仅带首批评论，返回继续加载游标和作者/合集资料。新客户端补取旧内容并按页加载，旧客户端仍会停在首屏，需协调升级。所有分页继续验证作者状态、内容审核状态、拉黑及本人权限。

12. 私信：迁移 020/021 增加消息及会话 revision 与分页索引。新同步协议返回部分消息，必须与客户端更新配套，旧客户端无法正确合并部分会话。全局未读数携带快照游标；空同步不再重复查询。客户端升级后不在未登录状态恢复旧聊天文件，登录后仅迁移当前账号自己的待发送内容；已确认历史由服务端分页获取。后台缓存错误会显示提示，退出会清除本账号本地消息缓存。生产发布前应备份数据库并验收跨设备发送、撤回、已读、旧历史和账号切换。

13. 实时：反向代理转发 `/api/ws` Upgrade/Connection/Authorization，空闲超时至少 90 秒。每个实例额外占用一个 PostgreSQL LISTEN 连接；数据库角色需允许 LISTEN/NOTIFY，事务连接池代理必须为监听提供直连或会话模式。提示本身不持久化，断开期间由数据库游标补齐；健康客户端 60 秒校验，连接失败时备用轮询最高约 30 秒。默认每实例 2000 个、每账号每实例 4 个连接，账号失效由下一次心跳重验关闭；这些上限不是压测容量承诺。关闭时停止心跳/监听并断开 socket。

14. 审核预算：迁移 022，生产必填 `MODERATION_DAILY_CALL_LIMIT`（整数 0–1000000）。这限制每个北京时间自然日的供应商调用数，文本分段、各张图片分别计数，不是人民币预算。按自己的审核套餐确定额度；0 暂停自动审核。各实例必须使用一致值，勿在已消耗额度之下调整后误认为费用会追回。相同输入当天复用，未知超时仍占额度且当日不重发；跨日再次提交可能重新计费。进程崩溃后留下 reserved 记录也暂转人工，不自动假定未扣费。`moderation_daily_usage` 可只读查看使用量，临近上限/转人工积压应接现有运维告警。

15. 运行环境：使用 Node 24.21.0，在目标 Linux 主机 `npm ci --registry=https://registry.npmjs.org`，不要搬运本机 node_modules。升级后的包审计为 0，不代表无需后续维护。Express 的 qs 6.16.0 override 需保留至其上游依赖修复后再验证移除。参考 [Nodemailer 公告](https://github.com/nodemailer/nodemailer/security/advisories/GHSA-8m3c-c648-2xjj)、[urllib 公告](https://github.com/node-modules/urllib/security/advisories/GHSA-hq3h-g68c-hp78)、[qs 公告](https://github.com/ljharb/qs/security/advisories/GHSA-4mjr-xmp4-gh2g)。

16. 启动配置与退出：生产启动拒绝错误 NODE_ENV、Mock 审核、无效数字/SMTP/非 HTTPS API/已知占位密钥。TRUST_PROXY 仅接受 false、明确网段/地址或 1–5 跳；需按实际代理拓扑填写。HTTP 请求 60 秒、头部 15 秒、keep-alive 5 秒；反向代理业务响应等待应覆盖最长审核调用，WebSocket 空闲超时另设。SIGTERM 后最多 25 秒等待当前请求，长审核可能被关闭，但相同提交 ID 可恢复。数据库 TLS/CA、私网边界、RDS 备份保留与恢复演练、进程监控、错误/人工队列/额度告警、云 RAM 最小权限需要单独确认线上配置；本轮未访问或修改这些生产配置。
