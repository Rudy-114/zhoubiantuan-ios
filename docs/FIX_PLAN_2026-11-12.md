## 1. 阶段 A：快速见效

### F01 首页不再被自动重置；侧滑返回改用系统手势

**问题**
- `ZhouBianTuan/HomeViews.swift:82` 的 `.task(id: pageQuery)` 每次首页重新出现（从详情返回、切 Tab 回来）都调用 `loadContentPage(pageQuery, reset: true)`，并生成新的 `refreshSeed`（`ZhouBianTuan/ContentPaging.swift:100`），服务端重新排序。用户返回后列表被换成另一批 30 条。
- `ZhouBianTuan/ZhouBianTuanApp.swift:145/160/177/194/212` 给每个 Tab 注入了一份完整根视图作为侧滑背景（`navigationBackdrop`）。`InteractiveBackSwipeModifier`（`ZhouBianTuan/CommonComponents.swift:62-164`）在每个二级页面下方渲染这份副本：第二个 `HomeView` 会再触发一次重置、再记一轮曝光、再加载一遍图片；并且背景永远是根页面，从三级页返回时背景是错的。

**改法**
1. `HomeView.task`：只在未加载时加载。
   ```swift
   .task(id: pageQuery) {
       let state = store.pageState(pageQuery)
       guard !state.isLoaded, state.requestID == nil else { return }
       await store.loadContentPage(pageQuery, reset: true)
   }
   ```
   `reset: true` 之后只允许出现在：下拉刷新、错误重试、离线快照恢复后的后台刷新（`MockAppStore.restoreOfflineFeedIfAvailable` 已有）。
2. `loadContentPage`：`reset == true` 且该 query 已有进行中的 reset 请求时直接返回，避免并发重置。在 `ContentPageState` 加 `isResetting` 标记即可。
3. 侧滑返回改为系统手势：
   - 删除 5 处 `.environment(\.navigationBackdrop, AnyView(...))`，删除 `NavigationBackdropKey`。
   - `InteractiveBackSwipeModifier` 改成薄封装：不再有 `ZStack`、`offset`、`DragGesture`、backdrop，只挂一个 `UIViewControllerRepresentable`，在 `viewDidAppear` 里启用 `navigationController.interactivePopGestureRecognizer`。
   - 导航栏隐藏时系统手势默认失效，需要自己提供 delegate。**delegate 必须在栈深为 1 时返回 false**，否则在根页面边缘滑动会卡死界面：
     ```swift
     final class PopGestureDelegate: NSObject, UIGestureRecognizerDelegate {
         weak var navigationController: UINavigationController?
         func gestureRecognizerShouldBegin(_ g: UIGestureRecognizer) -> Bool {
             (navigationController?.viewControllers.count ?? 0) > 1
         }
     }
     ```
     delegate 由 Controller 强持有，`viewWillDisappear` 不需要还原。
   - 保留 `interactiveBackSwipe(onComplete:)` 的函数签名，避免改 13 个调用点；`onComplete` 参数忽略（系统 pop 会自动更新 `NavigationStack(path:)`）。确认没有调用点依赖后，删除 `popNavigationRoute` / `popNavigationRouteEnabled` 环境值和 `RootView.popXxxRoute`。
4. `PostCard.onAppear` 的曝光上报不变（`impressedFeedPostIDs` 已去重）。

**验收**
- 首页滑到第 3 页，进详情再返回：列表内容、顺序、滚动位置都不变；抓包确认没有新的 `/feed` 请求。
- 切到"消息"再切回首页：同上。
- 下拉刷新仍会换一批。
- 所有二级、三级页面左边缘右滑能返回，背景是真正的上一页；根页面左边缘滑动无反应、不卡死。
- 详情页图片横滑不触发返回。

## 2. 阶段 B：图片链路

### F02 + F03 新图片管线：全量内存缓存、按尺寸降采样、后台解码

**问题**
- `ZhouBianTuan/OfflineFeedCache.swift:143-155`：`RemoteImageCache.data` 只对 `allowedKeys` 中的 URL 生效，范围只有每页前 10 帖；其余图片每次出现都重新下载。
- `ZhouBianTuan/CommonComponents.swift:285-309`：`RemoteImageLoader` 是 `@MainActor`，`downsampledImage` 在主线程执行，且一律按 1600px 解码；没有解码后图片的缓存。

**改法**
1. 新建 `ZhouBianTuan/ImagePipeline.swift`，提供：
   ```swift
   enum ImagePipeline {
       /// 同步命中内存缓存，供视图首帧直接显示，避免占位闪烁
       static func cachedImage(url: String, accountID: String, maxPixel: Int) -> UIImage?
       static func image(url: String, token: String?, accountID: String, maxPixel: Int) async throws -> UIImage
       static func clear(accountID: String)   // 登出、切换账号
       static func clearAll()                 // 内存警告
   }
   ```
   - 解码后缓存：`NSCache<NSString, UIImage>`，key = `账号摘要|URL摘要|maxPixel`，`cost = 宽×高×4`，`totalCostLimit` 约 120 MB。
   - 原始 Data 仍走 `RemoteAssetRequest.data`（保留请求合并）。
   - 解码放到 `Task.detached(priority: .userInitiated)`，`CGImageSourceCreateThumbnailAtIndex` 增加 `kCGImageSourceShouldCacheImmediately: true`。
2. `RemoteImageCache` 拆成两级规则：
   - **内存**：所有 URL 都可缓存（本次会话有效）。
   - **磁盘**：仍只写 `allowedKeys` 内的 URL（保持"私信图不落盘"的现有隐私约束）。
   即：`data(for:)` 和 `insert` 去掉对内存缓存的 `allowed` 限制，磁盘读写保留。
3. `RemoteImageView` / `RemoteImagePreview` 增加参数 `maxPixelSize: Int`，调用点按显示尺寸传值（点数 × `UIScreen.main.scale`，向上取到档位）：

   | 场景 | 档位 |
   |---|---|
   | 头像（≤ 96pt） | 256 |
   | 信息流卡片、宫格 | 720 |
   | 详情大图、聊天大图 | 1600 |
   | 个人页背景 | 1280 |
4. `RemoteImageLoader.load` 开头先查 `cachedImage`，命中则直接 `.loaded`，不经过 `.loading`。
5. 登出/切换账号（`MockAppStore.invalidateSessionWork` 及现有 `RemoteImageCache.shared.remove(accountID:)` 的调用点）同时调 `ImagePipeline.clear`；监听 `UIApplication.didReceiveMemoryWarningNotification` 调 `clearAll`。

**验收**
- 首页滑两屏再滑回：已看过的卡片图片直接显示，无占位；抓包无重复的 `/assets/` 请求。
- Instruments Time Profiler：滚动时主线程不出现 `CGImageSourceCreateThumbnailAtIndex`。
- 新增单测：内存缓存按账号隔离；`clear(accountID:)` 后取不到；未登记 URL 不写磁盘。
- 现有 18 个 iOS 测试仍通过。

### F09 图片代理加缓存头和条件请求

**背景** CDN 尚未接入（ICP 备案中），本任务不做 OSS 直连，只降低代理成本。

**改法**
1. `GET /assets/*`（`backend/src/routes.js:71-97`）：
   - 用 `upload_tickets.sha256` 作为 `ETag`（查不到时不发 ETag）。把这个查询并入 `canReadAsset`，一次 SQL 返回 `allowed` 和 `sha256`。
   - 请求带 `If-None-Match` 且匹配时，权限校验通过后直接返回 304，不读 OSS。
   - 响应头改为 `Cache-Control: private, max-age=300`，保留 `Vary: Authorization`。
2. 进程内对 `canReadAsset` 结果做 30 秒 LRU 缓存（key = `objectKey|viewerId`，上限 5000 条）。**只缓存 allowed = true**；拉黑、下架最多延迟 30 秒生效，在代码注释里写明。
3. iOS `RemoteAssetRequest`：保持 `urlCache = nil`（客户端有自己的缓存），不需要改。

**验收** 集成测试：第二次带 `If-None-Match` 的请求返回 304；帖子下架 31 秒后旧图返回 404；无权限用户始终 404。

| 私信 body | 2000 | 发消息 |

### F25 验证码发送防滥用

**问题** `backend/src/routes.js:49-56`：限流键为 IP+邮箱+用途，换邮箱即绕过；对同一邮箱每 60 秒可发一封，无每日上限。

**改法**
1. 在 `/auth/email/send-code` 上再串两个 limiter（Postgres 存储）：
   - 每 IP：10 次/小时。
   - 每邮箱（不含 IP）：5 次/小时、10 次/天。
